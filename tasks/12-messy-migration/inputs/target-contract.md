# Customer migration contract
For this bounded synthetic exercise, a valid email has exactly one @, a nonempty local part, a dotted nonempty domain, and no internal whitespace. This is a fixture rule, not comprehensive Internet email validation. Normalize valid addresses by stripping outside whitespace and lowercasing. Do not normalize phone numbers or infer identity from them.
For duplicate normalized email, choose the smallest imported_at timestamp, breaking ties by smallest original ID, as the canonical survivor. Preserve its original ID and all raw source fields somewhere durable. Map the other valid source IDs to it without losing their raw data. Invalid, null and blank emails require quarantine with source ID, raw data and reason.
The target can be new tables or an evolved schema. It must provide uniquely constrained canonical emails, complete source-to-canonical mapping, quarantine, and a durable original-data record. For the supplied eight records: valid source rows 5, canonical identities 3, merged aliases 2, invalid rows 3. Thus 3 canonical + 2 aliases + 3 quarantine accounts for 8 source rows. Keep source-row counts distinct from identity counts.
Document transaction/backup strategy, make reruns safe, and demonstrate restoring a disposable DB from the preserved pre-migration state. No prewritten migration solution or rollback script is supplied.
